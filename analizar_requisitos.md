# analizar_requisitos

## Objetivo
Transformar una idea expresada por el usuario en requisitos funcionales claros.

## Informacion que recibe
- Descripcion del problema o programa deseado.

## Proceso
1. Identificar que necesidad resuelve el programa.
2. Extraer los datos de entrada.
3. Definir los procesos principales.
4. Determinar las salidas esperadas.
5. Anotar reglas y validaciones necesarias.

## Informacion que devuelve
Un documento de requisitos funcionales.

## Formato esperado del resultado
- Objetivo.
- Datos de entrada.
- Procesos.
- Datos de salida.
- Reglas del programa.

## Reglas para utilizarla
- Conservar la intencion del usuario.
- Escribir requisitos medibles y sencillos.
- Indicar una regla de validacion cuando una entrada pueda ser incorrecta.
- No decidir detalles tecnicos que pertenezcan al diseno.
